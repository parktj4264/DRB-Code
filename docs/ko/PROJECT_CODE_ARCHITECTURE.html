00 · How to read

먼저 이것만 기억하면 된다

DRB-Code는 화면과 스크립트라는 두 개의 입구가 있지만, 실제 분석은 항상 같은 main.R 엔진을 사용합니다. GUI는 계산 로직을 복제하지 않고 옵션을 안전하게 구성해 기존 엔진에 전달합니다.

핵심 문장: 일반 사용자는 run_gui.R 또는 run.R만 실행한다. 데이터 로딩·Sigma·PPT·Spotfire 로직은 src/가 담당하고, main.R이 그 순서를 조정한다.

04 · Entry points & configuration

실행 파일과 설정 파일의 책임

ENTRYrun_gui.R

Shiny와 Preview에 필요한 모듈만 먼저 로드한 후 launch_drb_gui()를 호출합니다. 일반 GUI 사용자가 실행하는 파일입니다.

수정 시점 · GUI 부팅 순서 또는 필수 패키지가 바뀔 때
ENTRYrun.R

Raw, ROOTID, REF/TARGET, Good-chip, 출력 여부, PPT 핵심 옵션을 선언하고 main.R을 실행합니다. 배치·재현 실행에 적합합니다.

수정 시점 · 사용자에게 노출할 기본 실행 옵션이 바뀔 때
COREmain.R

모듈 source와 Stage 0~3 호출 순서만 책임집니다. 도메인 세부 로직을 직접 넣지 않는 것이 원칙입니다.

수정 시점 · 새로운 파이프라인 단계가 추가될 때
CONFIGconfig/general_config.R

NA_POLICY와 Good-chip 기본 함수를 정의합니다. GUI/실행값이 없을 때 사용하는 분석 기본 정책입니다.

수정 시점 · 조직 공통 Good-chip/NA 정책이 바뀔 때

METRIC_PARAMS 이름 있는 리스트로 개별 메트릭 인자를 덮어씁니다. 함수 코드를 바꾸지 않고 튜닝할 때 사용합니다.

수정 시점 · PPT 디자인·plot 표현·페이지 정책이 바뀔 때

→

BOOTsrc/bootstrap/libs.R

BOOTsrc/bootstrap/io_utils.R

임시 파일 → rename 방식의 atomic write/copy와 retry를 구현합니다. 파일 잠금·부분 저장 위험을 줄입니다.

BOOTsrc/bootstrap/runtime_config.R

설정 파일 로드, 키 검증, 우선순위 병합, 실행값 수집, 확정 설정 로그를 담당합니다.

BOOTsrc/bootstrap/ppt_defaults.R

PPT 설정의 완전한 기본값 목록입니다. config가 일부 키만 제공해도 안정적으로 전체 설정을 완성합니다.

DATAsrc/01_load_data.R

CSV 헤더 검사, ROOTID 매핑 검증, MSR 선택, 숫자 변환, Good-chip 필터, GROUP join을 수행합니다.

STATSsrc/02_calc_stats.R

그룹 통계와 raw access cache를 만들고 metric plugin을 실행해 Sigma, 방향, issue/timing 정보를 생성합니다.

OUTPUTsrc/05_finalize_outputs.R

results.csv, 실행 이력, 파라미터 로그, metric issue를 저장하고 PPT/Spotfire 모듈을 dispatch합니다.

01_load_data.R · 입력 데이터가 분석 테이블이 되는 과정
  • read_csv_header(): 대용량 본문을 읽기 전에 헤더만 확인합니다.
  • validate_rootid_map(): ROOTID/GROUP 필수 컬럼과 ROOTID별 단일 GROUP 매핑을 보장합니다.
  • resolve_raw_msr_columns(): msrinfo.csv FIELD 교집합을 우선하고, 없으면 PARTID 뒤 컬럼을 사용합니다.
  • load_and_filter_data(): 필요한 컬럼만 읽고 Cold 값이 있으면 Cold rule, 없으면 Hot rule, 둘 다 없으면 auto-good을 적용합니다.
  • run_stage_load_data(): Stage용 wrapper로 분석 데이터·MSR 목록·wafer count를 반환합니다.
02_calc_stats.R · 메트릭 플러그인 엔진
  • load_metric_functions()가 src/metrics/*.R을 source하고 metric_ 접두어 함수만 발견합니다.
  • build_metric_pair_stats()가 REF/TARGET 평균·SD·wafer count·valid chip count의 표준 입력을 만듭니다.
  • 필요한 메트릭에만 raw_access를 제공하며 cache로 중복 raw 접근을 줄입니다.
  • 메트릭 실패·길이·타입 오류는 issue collector에 기록하고 NA 정책에 맞는 fallback을 넣습니다.
  • calculate_sigma()가 메트릭/절댓값 쌍과 최종 Sigma_Score, Direction을 조립합니다.
src/metrics/ · 새 분석 지표를 추가하는 확장 포인트

함수 이름을 metric_으로 시작하고 pair_stats 또는 pair_stats, raw_access를 받도록 작성합니다. 반환값은 pair_stats 행 수와 같은 numeric 벡터여야 합니다.

metric_one_sigma(pair_stats)metric_*(pair_stats)metric_*(pair_stats, raw_access)

11 · Guardrails

안전성과 유지보수 장치

Atomic output

완성 전 임시 파일을 latest 파일로 보이지 않게 하고 rename/copy 재시도로 잠금 문제를 줄입니다.

Config validation

알 수 없는 key는 경고하고, named list·색상·numeric·category 범위를 정규화합니다.

Metric isolation

개별 metric 오류가 전체 실행을 즉시 망가뜨리지 않도록 issue와 fallback을 관리합니다.

GUI formula sandbox

Good-chip 수식은 비교·논리·기본 산술만 허용하고 함수 호출/임의 이름은 거부합니다.

Preview cache

대용량 Raw에서 선택 MSR만 보존하고 파일 signature와 조건이 같을 때 재사용합니다.

Template boundary

추적된 PPT 템플릿을 호환성 경계로 삼고 검사되지 않은 사내 PPT로 임의 교체하지 않습니다.

Git 주의: data/raw.csv, Spotfire 생성 CSV, 실행 이력, PPT 결과물은 실제 데이터가 포함될 수 있습니다. 배포 커밋 전 git status와 git diff --cached로 코드·문서만 포함됐는지 확인합니다.
